# Проверка реализации

Дата: 2026-11-12. Область: собственные auth handlers, HTTP/cookie transport,
криптографические adapters, SQLAlchemy/PostgreSQL, миграции и конфигурация.

## Инварианты

- Identity берётся из сохранённого пользователя; session.user_id совпадает с JWT sub.
- Успешный ответ с токенами отдаётся после commit сохранённой сессии/ротации.
- Использованный refresh не принимается повторно; replay фиксирует отзыв сессии
  даже при ошибке запроса. История активной сессии сохраняется.
- Смена пароля и отзыв всех сессий атомарны. Login/refresh/change-password
  используют одинаковый порядок блокировок, защищающий от гонок.
- Logout отзывает access и refresh текущей сессии, сохраняя другие сессии.
- Cookie auth требует разрешённого Origin и нестандартного CSRF-заголовка.
- Пароли и токены не возвращаются в ошибках валидации и не пишутся в логи.
- SQL параметризован. Auth bodies ограничены 16 KiB, пароль — 128 символами,
  Argon2 — четырьмя одновременными workers на процесс. Auth rate limit хранится в БД.

## Результаты

- Ruff format/check: пройдены.
- mypy strict для src: пройден.
- pytest: 53 теста в Docker на Python 3.14.10 и отдельном PostgreSQL 16.15.
  Проверены позитивные/негативные HTTP-сценарии, CSRF, поддельные JWT,
  чужой sub, отзыв, replay, реальные конкурентные транзакции, OpenAPI, HTTP 429.
  Отсутствующие записи возвращаются пустыми существующими DTO; отрицательные
  auth-сценарии проверяют отказ в доступе при незаполненных полях.
- Alembic: upgrade → проверка соответствия ORM → downgrade → upgrade,
  в выделенной тестовой схеме.
- pip-audit 2.10.1: известных уязвимостей не найдено. Локальный auth-template
  отсутствует на PyPI и проверен отдельно как исходный код.
- Bandit 1.9.4: находок нет. Предварительный запуск 1.8.6 оказался несовместим
  с Python 3.14; результат старой версии не учитывался.
- Gitleaks 8.28.0: исходники проверены, утечек не найдено.
- Runtime и development Docker-образы успешно собраны. Compose запускает БД,
  затем миграции и API; healthcheck и Swagger с хоста возвращают HTTP 200.
  Проверен реальный цикл signup → login → me → logout → отказ с отозванным токеном.
  Runtime работает с UID 10001, без `.env` и тестов внутри образа.
- Grype 0.121.3 проверил экспортированный архив runtime-образа в отдельном
  контейнере без Docker socket и host bind mounts. Результат: Critical — 0,
  High — 62, Medium — 64, Low — 17, Negligible — 49, Unknown — 15 совпадений.
  Это результаты сопоставления версий пакетов, а не подтверждение эксплуатации
  через API. Среди High отмечены Python 3.14.10 (CVE-2026-119170, scanner fix:
  3.14.11) и zlib1g (CVE-2026-76844, CVE-2026-85091, scanner fix:
  1:1.3.dfsg+really1.3.1-1+deb13u1). Для ряда остальных High источник Debian
  указывает wont-fix. Перед production-использованием нужны проверка применимости
  этих находок и обновление базового образа; образ не объявляется свободным от CVE.

Runtime packages проверены по метаданным установленных дистрибутивов:
FastAPI, SQLAlchemy, Pydantic/settings, pwdlib, Argon2, PyJWT, Alembic, AnyIO — MIT;
Dishka — Apache-2.0; Uvicorn — BSD-3-Clause; email-validator — Unlicense;
psycopg — LGPL-3.0-only. Psycopg используется как отдельная динамическая зависимость;
при распространении сохраняйте его лицензию и уведомления. Код city_api не копировался.
Версии и hashes пакетов зафиксированы в uv.lock.

## Ограничения проверки

Новый CI workflow переведён на Docker Compose; удалённый run этой версии ещё
не выполнялся. Локальные проверки выполнены исключительно в контейнерах.
Активный скан ZAP и нагрузочное тестирование не выполнялись; HTTP security
проверялась направленными ASGI-тестами на изолированной БД.
Base image tags обновляемые; перед production-сборкой нужен отдельный image audit
и фиксация digest в системе сборки. Настройка TLS, edge-защиты и reverse proxy
описана в README, но не является частью локального шаблона.
