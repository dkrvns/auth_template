# Проверка реализации

Дата: 2026-11-12. Область: собственные auth handlers, HTTP/cookie transport,
криптографические adapters, SQLAlchemy/PostgreSQL, миграции и конфигурация.

## Инварианты

- Identity берётся из сохранённого пользователя; session.user_id совпадает с JWT sub.
- Успешный ответ с токенами отдаётся после commit сохранённой сессии/ротации.
- Использованный refresh не принимается повторно; replay фиксирует отзыв сессии
  даже при ошибке запроса. История активной сессии сохраняется.
- Смена пароля и отзыв всех сессий атомарны. Login/refresh/change-password
  используют одинаковый порядок блокировок, защищающий от гонок.
- Logout отзывает access и refresh текущей сессии, сохраняя другие сессии.
- Cookie auth требует разрешённого Origin и нестандартного CSRF-заголовка.
- Пароли и токены не возвращаются в ошибках валидации и не пишутся в логи.
- SQL параметризован. Auth bodies ограничены 16 KiB, пароль — 128 символами,
  Argon2 — четырьмя одновременными workers на процесс. Auth rate limit хранится в БД.

## Ограничения проверки

Новый CI workflow переведён на Docker Compose; удалённый run этой версии ещё
не выполнялся. Локальные проверки выполнены исключительно в контейнерах.
Активный скан ZAP и нагрузочное тестирование не выполнялись; HTTP security
проверялась направленными ASGI-тестами на изолированной БД.
Base image tags обновляемые; перед production-сборкой нужен отдельный image audit
и фиксация digest в системе сборки. Настройка TLS, edge-защиты и reverse proxy
описана в README, но не является частью локального шаблона.

## Регистрация с кодом из письма

Проверка 2026-11-12, Python-код и проверки выполнялись только в Docker.

- POST `/auth/signup/code` принимает email, SMTP отправляет шестизначный код;
  POST `/auth/signup` требует email, пароль и код. До подтверждения пользователя
  нет в БД; существующие аккаунты продолжают входить по прежнему контракту.
- Срок действия — 10 минут, 5 неверных попыток, повторная отправка — раз в 45 s.
  В БД сохраняется HMAC-SHA256 с ключом сервера и привязкой к email и назначению,
  сравнение constant-time. Код и пароль исключены из repr DTO и HTTP-ошибок.
- Выдача/замена кода использует условный PostgreSQL upsert, подтверждение —
  блокировку строки. Создание пользователя и использование кода атомарны.
  Ошибочная попытка фиксируется до возврата HTTP 400; откат запроса её не стирает.
  После исчерпания попыток правильный код также отклоняется.
- SMTP выполняется после commit выдачи кода, без открытой транзакции БД;
  при ошибке код становится недействительным. Нет автоматических повторов
  SMTP-запроса при неопределённом результате. Принятие письма сервером SMTP
  не трактуется как подтверждение внешней доставки.
- Используется stdlib smtplib; новых Python/npm зависимостей нет. STARTTLS/SSL
  проверяют сертификаты, аутентификация без TLS запрещена. Четыре SMTP workers,
  timeout сетевой операции — 5 s по умолчанию. Логи ошибок не содержат адресов,
  кодов, SMTP-пароля или текста ошибки внешнего сервера.
- Локальный Mailpit v1.33.1 принимает письма без пересылки во внешние ящики.
  SMTP-порт не опубликован; web/API доступен на loopback:8025. Хранение ограничено
  100 письмами. Для pytest используется отдельный mailpit_test без host-портов.
- Ruff format/check, mypy strict, 76 pytest пройдены. Покрыты обязательность,
  формат, срок, привязка к email, одноразовость, лимит попыток, замена/ограничение
  отправки, ошибка SMTP, отсутствие секретов в ошибках/логах. Проверены реальные
  конкурентные запросы к PostgreSQL и доставка письма в тестовый Mailpit.
  С разрешения пользователя адаптированы сценарии регистрации в старых тестах;
  проверки login, refresh, logout, CSRF и смены пароля сохранены.
- Playwright: 3 сценария прошли, включая запрос кода в браузере, получение
  настоящего SMTP-письма через API Mailpit и завершение регистрации.
- pip-audit и npm audit: известных уязвимостей зависимостей не найдено.
- Bandit 1.9.4: High/Medium — 0; 2 Low B105 относятся к публичным паролям-примерам
  OpenAPI в presentation/schemas.py. Это не рабочие секреты и не автоматическое
  создание аккаунтов; правила сканера не отключались.
- Grype 0.121.3 проверил архив Mailpit v1.33.1 без Docker socket: Critical/High — 0,
  Medium — 3 (CVE-2025-60876 в пакетах BusyBox), Unknown — 1 (GO-2026-6859,
  Go stdlib 1.27.3, версия исправления по данным сканера — 1.27.4). Это совпадения
  версий, эксплуатация через регистрацию не подтверждена; образ доступен локально.

Доставка через внешний SMTP, TLS-подключение к реальному провайдеру, активный
ZAP и нагрузочная проверка почтовой отправки не выполнялись. Старые замечания
к базовому Python-образу выше остаются применимыми. Просроченные записи кодов
перезаписываются при повторном запросе на тот же email; периодическая очистка
таблицы средствами БД остаётся операционной настройкой, Python-скрипт не добавлен.

### Таймер повторной отправки

Кнопка повторной отправки блокируется на 45 секунд после успешной отправки.
Отсчёт рассчитывается по времени окончания и сохраняется при смене вкладок формы;
сброс busy после ошибки подтверждения не снимает блокировку. Запросы отправки
дополнительно проверяют таймер в API-клиенте. После сетевой ошибки блокировка
сохраняется, поскольку письмо могло быть принято SMTP. HTTP 429 продлевает её
по Retry-After. На сервере условный PostgreSQL upsert также использует 45 секунд:
отключение JavaScript и перезагрузка страницы не обходят серверное ограничение.
Для отклонённых запросов сохранён прежний консервативный Retry-After=60;
при обычной отправке UI и сервер допускают следующий запрос через 45 секунд.
Существующие тесты не изменялись. Новые проверки покрывают границу 44/45 секунд,
блокировку кнопки при ошибке подтверждения, переключение вкладок, повторный
запуск отсчёта и соблюдение Retry-After после HTTP 429.
Итоговые проверки в Docker: сборка Vite, TypeScript strict, Ruff format/check,
mypy и все 78 pytest прошли; 5 Playwright-сценариев прошли. Новых зависимостей
или миграций нет. Gitleaks проверил diff; утечек не найдено.
